What to put in a first message

It helps us to know, in a few lines:

  • What you run now. The playout system, or other equipment, that the work would replace or sit beside.
  • What you want to do. How many channels, where the schedule comes from, and what you have to be able to show afterwards — an as-run record for a regulator, for example.
  • Formats and outputs, if they matter. The resolution and frame rate of each output, how many outputs, and whether they take a reference.
  • For one of the free tools. Which tool, what --version prints, the operating system you run it on, and the command you ran with what it printed. Output can carry folder and file names, user names and machine names; take out anything you would rather not send.
